# AI 场景改造与试验工作流

本轮只修改 Web 前端、.NET 后端和 Python Agent。引擎仍固定为 `0b8829a864ff53ad0ad2c7ded56ef433325a836a`，没有上游补丁。

## 使用入口

登录并打开项目，点击编辑器顶部的 **项目工具**：

- **本次打开后的变化**：比较当前场景与打开时的基线，显示实体、组件、属性的前后值，以及完整项目文件的新增、修改和删除。点击“刷新差异与笔记”重新读取。
- **创建试验副本**：先将原项目完整保存，再按该不可变修订复制场景、脚本、资源和配置，创建独立云端项目并打开新的 WASM 会话。副本显示来源版本；副本的后续保存不修改原项目。
- **固定步数位置验收**：选择实体、步数、最终世界 Y 区间和最后三次采样允许的最大变化，再执行。预览结束后恢复编辑模式，模拟位置不会写回编辑场景。
- **项目知识**：读取或编辑项目笔记。新建时使用英文、数字、下划线或短横线作为标识。并发修改冲突需要重新读取，不能覆盖其他人的新版本。

AI 助手可以执行批量编辑、获取任务差异、运行位置验收、读写项目笔记。任务完成后展开 **执行证据与变更**，查看工具参数、结果、语义差异和验收轨迹。历史对话也可以读取这些持久记录。

示例需求：

> 在试验副本中创建地面和一个动态刚体方块，先读取组件 schema，再用一次事务完成。模拟 180 步，检查方块最终世界 Y 在 -0.05 到 0.1，最后三次采样变化不超过 0.02。报告真实结果，并将观察记录到项目笔记。

示例区间只适用于相应的地面高度和方块尺寸；Agent 应先确定验收条件，不得为了通过而放宽条件。

## 工具契约

| 能力 | 实现与边界 |
| --- | --- |
| `scene_apply_patch` | 一次提交 1–128 条实体或组件操作，经过参数、场景版本和原生事务校验；全部成功才提交，一次撤销对应整组操作。不会拆成逐条提交，不包括源文件写入。 |
| `scene_get_diff` | 比较本次任务第一次观察的场景快照与当前快照，按稳定 ID 和 schema 比较，可包含同期人工修改。最多返回 500 条变化，超出有截断标记。 |
| `runtime_validate` | 编辑模式下启动新预览，每步固定 1/60 秒；1–600 步，最多 60 个采样间隔、16 个实体轴向检查。使用 `preview.snapshot` 的运行时归档，实体 uint64 ID 全程保持字符串精度。 |
| `project_knowledge_list` / `project_knowledge_save` | 每项目最多 100 条笔记，每条最多 4000 字符；保存要求 `expected_version`，首次为 0。记录来源任务和引擎版本。 |
| `capability_search` / `capability_describe` / `capability_invoke` | 搜索已实现工具、取得确切 schema、按版本 1 调用。调用仍经过完整 schema 和会话授权；不允许任意 RPC 或递归网关调用。 |

`scene_apply_patch` 接受 `entity.create/delete/rename/set-parent`、`component.add/remove/patch`。创建实体时指定新的非零 uint64 字符串 ID；组件和属性 ID 必须来自当前 schema。`scene_version` 来自最新读取，冲突后必须重读。重试必须保留原 `request_id`。

位置验收返回 `passed`、每项的实际值和末尾采样跨度、步数、采样轨迹及引擎版本。`ok: true` 表示工具执行成功；`passed: false` 才表示验收条件未满足，两者不能混同。稳定性只比较最后三次采样，采样间隔需允许至少三次采样。运行阶段同步推进，避免渲染帧插入额外物理步；最多 600 步仍可能使复杂场景短暂阻塞页面。

语义差异覆盖 Inspector 可见的实体、组件和属性；脚本源文件通过文件差异报告，不能解析的归档变化另有标记，不声称覆盖全部脚本字段或资源内部语义。项目笔记都是 `unverified_observation`，来源信息不使内容自动成为正确结论，也不是自动生成的因果知识图谱。

试验副本是独立项目，并记录来源项目和基线修订，不提供自动合并回原项目。复制的是引擎项目内容，不继承原项目的聊天历史和知识笔记。删除来源项目后副本仍可用。云端创建副本与内容上传不是单一事务；上传失败会报告已创建的副本 ID，原项目保留。

## 持久化与升级

三个服务需要一起更新。后端启动时自动应用 SQLite 迁移 `007_ai_workspace.sql`，新增工具事件、项目笔记和试验来源表；无需重编上游引擎。前端增加 `yaml` 依赖，按锁文件安装。

工具事件按项目、任务、会话和请求 ID 保存，包括参数、结果及 `queued/succeeded/failed/outcome_unknown` 状态，接口按 100 条分页。超过 32768 字符的参数或结果保存截断说明、SHA-256 和前 8192 字符，模型当次仍收到完整结果。重启或任务结束时尚未确认的命令标记为结果未知，不推断回滚。发现工具本身在 Python 执行；持久事件记录实际提交给后端的能力调用。

持久证据与已有项目检查点可供复查，但命令队列仍在内存中，不提供任务断点续跑。位置验收不证明脚本没有异常、不检测连续碰撞事件，也不评价性能或游戏体验。

## 验证

前端：`npm test`、`npm run build`。

后端：`dotnet build TomCat.Api -c Release --no-restore`，以及 `node --test tests/ai-workspace.test.mjs tests/ai-conversations.test.mjs tests/api.test.mjs tests/editor-sessions.test.mjs`。

Python：`.venv/Scripts/python.exe -m pytest -q`。

跨服务：在前端目录执行 `node tests/workspace-browser.mjs`。需本地 Chrome、构建后的后端、Python 虚拟环境及现有引擎产物。脚本使用临时数据库和确定性模型，实际运行 LangChain → MCP → 后端 → 浏览器 → WASM；验证批量事务失败不留半成品、一次撤销、物理验收通过与失败、作者场景保留、证据落库、界面验收与笔记编辑、完整副本文件一致和原项目不受副本修改影响。不代表已测试外部模型供应商的生成质量。
