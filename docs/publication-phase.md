# 公开发布：独立交付阶段

状态：设计待实现。当前版本提供完整云端项目保存、编辑器 `preview.control` 和独立 TCPAK 播放器；没有公开发布服务。旧版展示草稿只展示作品介绍，不代表已有构建产物或公网作品。

## 输入和完成条件

发布输入必须是账号拥有的、已保存的不可变 schemaVersion 2 修订，包含项目配置、全部资源和 `.tcmeta`。草稿或当前内存场景不能直接成为构建输入。引擎提交和工具链必须匹配锁文件；公开运行目标为 Web，先拒绝当前 Web 不支持的脚本和资源能力。

完成条件：另一个未登录浏览器通过公开 URL 读取已发布版本，下载经过校验的 TCPAK，在 TomCatPlayerModule 中实际运行。保存成功、Play 成功或作品介绍页面出现都不满足此条件。

## 后端构建任务

拟新增 `POST /v1/projects/{id}/builds`，接收明确的 revisionId、target=web 和幂等键，验证所有权并固化构建输入；返回 202 和 buildId。`GET /v1/projects/{id}/builds/{buildId}` 读取排队、运行、成功、失败、取消状态及日志摘要。任务有账号额度、超时、输出大小限制和持久化状态，服务重启后能够恢复或明确标记中断。

独立受限 worker 下载并校验修订文件，写入任务专属目录，用锁定引擎官方 Cook 工具生成 TCPAK。不要在 HTTP 请求线程内执行编译，也不要将用户输入拼入 shell。网络、路径、进程时间、CPU 和内存需要限额。Cook 日志不得泄露服务器路径或凭据。

活动场景 archive 与 Assets 中的场景文件需要在构建前统一：确定稳定场景资产 Handle、写回对应场景和 `.tcmeta`、更新 BuildSettings 的入口及场景列表，再运行官方校验器。当前浏览器会话 Handle 会重建，不能直接把它当作发布资产 ID。存在多个未落盘场景时应阻止构建，提示先保存所需场景。

## 产物存储和发布记录

Cook 成功后校验 TCPAK 及 Web 运行兼容性，产物写入独立不可变存储，记录 SHA-256、大小、引擎提交、输入修订和构建 ID。先完成产物持久化，再原子提交构建成功状态；失败任务不可发布。临时目录和无引用产物有保留期限；已发布版本引用的产物不能被清理。

拟新增 `POST /v1/projects/{id}/releases`，接收成功的 buildId 和作品信息，校验所有权并创建不可变 releaseId。公开 `GET /v1/releases/{releaseId}` 返回公开元数据和产物地址，绝不暴露工程源资源、账号 Cookie 或私有修订。撤下作品通过独立接口处理，不能删除历史记录来模拟回滚。

## 前端和部署

编辑器先完整保存，用户再触发构建。界面显示排队、进度、失败原因、重试和成功产物；构建成功后用户才能发布。作品页根据 releaseId 加载固定版本 TCPAK，下载长度和 SHA-256 校验通过后交给 Player；失败时显示可恢复错误。页面必须继续提供 COOP/COEP，跨域产物必须提供匹配的 CORS/CORP 和正确 MIME。

## 阶段验收

1. 同修订重复构建的幂等性、并发和配额；越权请求不得读取任务或日志。
2. 多图片和 `.tcmeta` 项目 Cook 成功，入口场景及引用 Handle 完整，修改草稿不影响已有构建。
3. Cook 错误、超时、worker 崩溃、存储失败均不能产生可发布记录。
4. 未登录浏览器访问公开 URL，真实 Player 启动、运行和退出；损坏包拒绝加载。
5. 发布新版本不改变旧 releaseId；撤下和产物回收遵守引用与保留规则。
