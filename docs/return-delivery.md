## 复原范围

从用户提供的 Unity Return 工程提取 Main 菜单、教学关、Level1–Level5 和 final。保留像素图、音乐音效、原始世界坐标、尖刺触发的生死切换、推箱、按钮与门的连接和终点切关。原工程未改动。Main、教学和暂停界面通过原生 Canvas、RectTransform、UIImage、UIText、UIButton 复原，保留原层级、显隐、锚点、颜色、字体大小与按钮事件；1920×1080 下采用原坐标，其他尺寸等比适配完整构图。角色运动采用固定 120 Hz 模拟与显示插值；原 Unity 物理步长为 50 Hz。

此前菜单误用了原场景中未激活的标题/按钮图片，并自行添加侧栏文字；先前玩法通过记录不构成原版界面还原的证据。本次重新读取 Main.unity 的实际激活层级，并打开原工程 Unity 6.2 截图核对。教学说明、暂停面板、死亡世界红色遮罩和终章文字也按源数据补齐。暂停背景保留 Unity 内置 Background 的 32×32 像素、10 像素边框和 PPU200，转换为九个原生 UIImage，避免用纯白矩形替代原九宫格。导出来源及哈希随样本 Reference/UnityBuiltins 保存。

实际 Unity 暂停截图又识别出两处独立差异。源场景 fileID 10907 对应的是 `UI/Skin/Background.psd`，中心像素为 214；先前误映射的 `UISprite.psd` 实为 fileID 10905，中心像素为 245。同版本 Unity 的资源身份查询和 GPU 原始读回确认了对应关系，不靠调色补偿。另一方面，旧 OpenGL 混合把源透明度又乘入输出 alpha，导致网页按 CSS 背景再次合成而偏亮。浏览器回归使用原版暂停截图中的 RGB `(135,136,141)`，仅容许 2 个色阶的舍入差异；单纯“看起来是灰色”不足以通过。

可玩地图实际使用 27 个 Tc `Tilemap2D`，合计 770 格；未用一张关卡图片替代可编辑网格。单个世界最多约 160 格。当前 Tc 缺少原生 Tilemap 碰撞组件及托管 Cells 读取接口，因此编辑后通过同步工具生成碰撞数据；未修改的图层保留源 CompositeCollider2D 轮廓，修改图层使用导入素材的轮廓并合并相邻矩形。

## 稳定帧耗时的处理

关卡对象、组件引用、64 个装饰遗骸及 5 个音频源在启动时准备并复用。只向引擎提交发生变化的变换、精灵、文本和显隐状态；关卡切换重新启用已有实体。碰撞数组预分配，不在固定步长循环分配对象。网页隐藏与恢复重置计时，模拟限制补步次数，避免后台停留时间变成一次过大的更新。

菜单阶段收集所有界面字符（包括换行）预生成字体图集，并在零音量下预热五个音频源，停止后保留原生 voice 和 PCM 缓冲区。音量在创建音源时就设为零，避免属性延迟提交而 Play 即时执行造成短暂出声。测试同时检查实际输出静音、开始游玩后的正常音量和缓冲区复用。

补齐原 UI 后，实际截图暴露了另一个启动问题：131 张纹理按帧分批预载时，旧的三帧字体/音频就绪条件不能代表纹理已完成，首次暂停可能短暂显示洋红占位。示例现在显式请求全部运行时纹理，并通过原生纹理状态确认 GPU 已发布，完成后才显示菜单和启用操作；27 张整图参考 PNG 不参与运行时预载。等待阶段每帧查询首个未完成资源，已完成项不重复查询；无效资源、失败加载和缺少所需引擎能力均明确报错，不用固定延时推断成功。

下落箱子会对玩家进行向下扫掠检查，避免穿透并持续重叠；玩家移开后箱子继续下落。这是轴向运动模型，不模拟原 Unity 动态刚体的质量、冲量和完整箱子堆叠反馈。

第三关下箱的原始 Y 为 -6.66，碰撞框偏移 +0.06、高度 0.96，底边因此位于 -7.08，比地板顶面 -7 低 0.08。旧扫掠只处理从地板上方开始的下落，漏掉了这次初始重叠，箱子随即落出场景。修复保留原坐标，在静态几何重建后对整个碰撞集合求最短有效分离位移，并同步插值起点。初版逐矩形分离在第四、五关实际几何上可能反复挤回；最终实现用全体边界候选检查消除了该反例。18 项 C# 场景与 19,352 个有限网格候选验证通过；扫描不代表所有可编辑地图和动态相互作用都已穷尽。

用户指出的转向后角色倒立，已定位为负缩放经矩阵分解后遗留额外旋转。示例改用正尺寸和绕 Y 轴半周旋转实现水平镜像；上下翻转对应绕 X 轴旋转。原图与烘焙纹理无需翻转。验证读取实际 GPU 顶点和 UV，区分纹理上传与变换方向，覆盖左右转向后重开。

图片保留原 Gamma 像素值，关闭无用 mipmap。角色与地刺上方的白线来自旧引擎硬编码 Linear + Repeat：透明顶部边缘混入了纹理底部的不透明像素，原图裁切本身没有错。本次保留原 TextureImporter 的过滤和边界参数：工业像素图使用 Nearest + Clamp，原双线性 UI 图片仍使用 Linear + Clamp。上游 [PR #37](https://github.com/chnnasn/TomCat_Engine/pull/37) 增加导入、烘焙、OpenGL/Vulkan 渲染及编辑器采样设置；非默认采样使用 TCTX v2，默认采样继续输出兼容的 v1。

## 验证方法

`npm test` 校验首页入口、TCPAK 每项哈希、资源句柄、源工程 ZIP、全关卡地图和宿主计时恢复。`node scripts/return-tilemap.test.mjs` 在临时项目中实际绘制一个格子，验证保存后构建不会覆盖编辑、碰撞会同步改变，擦除后恢复原始数据。`node tests/return-physics.mjs` 编译真实 C# 物理代码，检查平台、墙壁、推箱等规则以及 100,000 次模拟的分配情况。

`tests/return-browser.mjs` 使用发布包和普通键盘操作检查开始、跳跃、真实尖刺切换、重开、暂停、静音、全屏、音频输出和退出清理。`tests/return-levels-browser.mjs` 使用单独复制并烘焙的 QA 工程，检查七个关卡的两个世界。副本保留真实 `Awake Load(0)` 菜单预热，严格等待 `ready → selected → initialized` 三个有序标记，再执行测量。关卡选择和只读诊断键仅存在于副本；测试前后核对生产工程、TCPAK、ZIP 和 manifest 哈希。

新增第三关两箱存活与边界断言，初始和闲置后必须分别落在 Y=-6.58、Y=-0.58，移动和跳跃后仍须在场内。新断言对保留的旧证据会按预期失败。另以 `TEST_RETURN_LEVEL3_COMPLETE=1` 独立检查第三关自然解谜：选关后仅用普通游戏按键放置下箱、触尖刺换界、登三级台阶、推动上箱形成箱堆、回生世界跳上箱堆并到达原终点，严格验证 `win:3` 后进入第四关。教学关也以普通按键完成推箱、按钮、门和终点。尚未声称整个游戏已连续自然通关。

`tests/return-editor-browser.mjs` 下载实际 ZIP，恢复到隔离编辑器会话，验证原生 Tilemap schema、单格删除、撤销、重做、保存、场景重新打开及完整页面重载。测试使用隔离 API fixture，不向用户云端写入项目。此次发现并修复的大资源 Base64 正则调用栈溢出也有 4 MiB 文件回归。

补齐 UI 后，360 个文件的串行云端上传在真实编辑器窗口中超出原 30 秒保存要求：导出约 0.47 秒，上传跨度 59.710 秒。改为最多 4 个并发任务后，同一工程在同一隔离 API fixture 的上传跨度为 19.162 秒，30 秒保存检查及页面重载通过。文件顺序、二进制内容、SHA 与条件修订语义保持不变；首个失败停止派发新任务，等待已发请求结束后才释放保存锁，全部文件验证通过才提交修订。该结果是本地模拟云端对照，不代表公网上传速度。

启用 `TEST_RETURN_NATIVE_INSPECTOR=1` 时，还会实际点击原生 Inspector 的 Cells 行删除按钮并执行原生撤销，核对场景格子数。此项覆盖 Inspector 逐格编辑，不把它表述为 Tile Palette 画笔自动化测试。

`tests/return-homepage-browser.mjs` 验证首页精选入口、详情页、实际源码 ZIP 下载、封面加载及 390 像素宽度下无横向溢出。

`tests/return-menu-browser.mjs` 通过实际发布包、原始按钮坐标与鼠标点击验证 Main 的 1920×1080、1280×720 和窄屏构图，以及开始、暂停、继续、重置、退出和重新打开。测试要求实际排队纹理数、请求数和 Ready 数相同且先于交互就绪，并在首次暂停截图检查原灰白面板像素，防止仅延后截图掩盖占位闪烁。原生 Application.Quit 在网页中关闭播放器、释放音频上下文，正常退出不显示运行错误。此项加入 CI，不依靠改写游戏状态验证按钮。

`tests/return-orientation-browser.mjs` 对实际上传的角色纹理及 GPU 顶点/UV 取证，覆盖连续左右转向、同朝向位置更新、跳跃、死亡切换和重开，共 20 次画面捕获，检查角色始终正立。本次还检查实际 GPU 纹理的 Nearest 与 Clamp 参数，防止烘焙或上传再次丢失原采样配置。首页封面也来自修正后实际运行的第三关。

浏览器证据同时保存页面获取的包哈希、实际 Service Worker 缓存的引擎 JS/WASM 哈希、浏览器/GPU/画布尺寸、原生日志、音频状态和截图。CPU 回调耗时与浏览器 rAF 间隔分开统计，不能把 rAF 频率当成显示器实际呈现帧数，也不能据此保证所有设备零掉帧。
