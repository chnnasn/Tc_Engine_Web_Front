# Rougelike 性能优化与回归

## 复现与原因

2026-10-16 用户反馈普通攻击明显卡顿。对已发布的 `5734c56a` 引擎和生产示例包进行 CPU 采样，在菜单左侧远离可破坏控件的位置连续空挥八次，每次间隔约 1.2 秒。

基线环境：Chrome headless，1440 × 1000，Intel UHD Graphics / ANGLE D3D11 硬件渲染，没有使用 SwiftShader。示例脚本 SHA-256 为 `d9b5c24cbea48c147f0df0c959c59b90d68b15c0af862d64161c2a9599b75d5a`，TCPAK SHA-256 为 `dab80522e621a167ce4d28192fc25d0e8edc8b15d05ed1cd920f5983b38f1ea5`。

| 基线测量 | 结果 |
| --- | --- |
| 待机 iframe rAF 回调 CPU 耗时 p95 | 12.075 ms |
| 八次攻击各区间最大回调 CPU 耗时 | 357–375 ms |
| 每次攻击超过 50 ms 的回调数 | 5–6 |

每次普通攻击创建 30 个原生刀光实体，在约 0.22 秒内持续更新其变换与颜色。引擎每追加一个延迟修改命令就丢弃投影缓存；下一次实体检查或属性读取又复制整个场景并重放全部已排队命令。场景复制还为每个实体重复执行线性名称查重。因此，少量瞬时效果触发了大量与整张场景规模相关的重复工作。

整段 CPU 采样中，`Scene::MakeUniqueEntityName` 独占约 4,976 ms，`ComponentCodecs::CopyAuthoringComponents` 约 710 ms。音频资源驻留缓存已经命中，重复攻击没有重新解码整段音效；音频入口本身也会经过上述实体检查路径。

## 验证方法

`tests/rougelike-performance-browser.mjs` 记录真实 iframe 的 rAF 回调执行耗时、Chrome CPU profile、渲染器和资源身份。默认走真实硬件 GPU；软件渲染只用于显式指定的对照。性能数字为此机器、此场景下的主线程回调时间，不等于 GPU 耗时、屏幕呈现间隔或通用 FPS 保证。

原始基线保存在本地 `.engine/rougelike-performance/baseline/`，不覆盖历史测量。修复后的对比必须在相同机器、场景与测量口径下执行，并另外检查命中、技能、死亡、全屏和暂停行为。

## 集中击杀暴露的第二个瓶颈

第一轮候选 `4d472cad` 的八次菜单空挥已降至最大 9.18–21.255 ms，均没有超过 50 ms 的回调，但这不足以证明整体性能达标。

在同一 Intel UHD 硬件上，以 1920 × 1080 全屏运行第十波 QA 场景，先自然生成敌人并持续聚敌 120 秒，再施放黑洞、时缓、蓄力斩和连续正反手攻击。QA 仅修改初始化以解锁技能、进入第十波并提供 1000 生命；正式包没有这些改动，敌人的出生、伤害、技能消耗与所有特效继续使用生产逻辑。

这一轮蓄力阶段实际击杀 28 个敌人，单次引擎所在 rAF 回调最大达到 **3,939.375 ms**，后续连续攻击阶段最大 **637.635 ms**。每个敌人死亡保留两个半片，每个半片由 18 条带表示，因此一次 28 杀会创建 1,008 个切片实体，另有原有粒子。采样中场景名称查重与延迟投影名称查重合计约 5.4 秒，仍存在大量同名创建时的重复扫描。

该轮记录位于隔离工作区 `.engine/rougelike-stress/2026-10-16T16-22-15-567Z-40808/`。它是中间候选的失败证据，不能当作已发布版本的同场景基线，也不能因功能脚本退出成功而称为性能通过。当时脚本尚未启用耗时阈值。

第二轮 `510140fb` 以 35 秒聚敌作快速定位：蓄力阶段 40 次击杀，最大回调 **897.320 ms**；连续攻击阶段 20 次击杀，最大 **135.770 ms**，启用的耗时阈值明确判定失败。其聚敌时长和随机敌人分布与上一轮不同，不能直接计算同场景提升百分比。证据位于 `.engine/rougelike-stress/2026-10-16T16-44-26-547Z-33548/`。

后续调用链分析定位到两项残余批处理开销：从命令队列逐条 `vector.erase` 造成反复后缀搬移，验证/提交每次创建又重建名称索引。另外，第二轮整段 CPU 采样的 `getParameter` 独占 29.18 秒，其中 99.6% 来自 Web 清屏读取 `GL_COLOR_CLEAR_VALUE`；调色过程的查询仅约 68 ms，FBO 完整性检查约 1.9 ms。调用链归因可以指导下一轮修复，但不代表这些采样总时长都发生在单次卡顿内。

第三轮 `fb5dcfc1` 修复队列搬移、提交名称索引及 Web 清屏查询后，仍在真实 Sprite/Transform 属性代理中发现名称索引失效过于保守。第四轮 `a9bd0f5d` 为经过审计的组件描述符增加保持实体名称的明确约定，保留其他注册提供器的失效边界；集中击杀最大回调降至 176.815 ms，但仍未通过门槛。

第五轮 `a1a42c53` 将纯元数据读取与组件场景复制分离：没有该场景命令的生命周期阶段不再复制整张场景，首次组件读取或写入仍建立隔离投影。音频清理也改为遍历音频源存储，同时保留销毁回调新建声音的关闭处理。35 秒快速定位中，蓄力阶段击杀 43 个敌人，p95 为 9.945 ms、最大 85.890 ms；连续挥刀击杀剩余 17 个敌人，p95 为 7.770 ms、最大 30.990 ms。唯一超过 50 ms 的回调仍被记录为失败。

第五轮尖峰的采样时轴经 6,501 个忙碌/空闲样本对齐，偏移约 +129 ms；目标区间为 profile 开始后 56,075.32–56,161.21 ms。采样主要位于属性入队、延迟命令回放、名称索引和变换处理，渲染仅约 1.6 ms，没有采到 GL 同步停顿。各调用链的 inclusive 时间相互嵌套，不能相加。继续检查发现，销毁任意名称都清空全部后缀游标，会让随后创建的无关碎片重复扫描；后续修复需要同时验证最低可用名称复用、嵌套括号、重复计数和非规范后缀。

上述迭代的聚敌时长、实际击杀和随机分布并不相同，因此只用于定位瓶颈，不作为同场景提升百分比。完整证据保留在本地 `.engine/rougelike-stress/`，正式验收另行记录最终提交和包哈希。

第六轮 `5798fcb1` 纳入定向名称游标回退及主线的带符号变换修复后，恢复 120 秒聚敌测试。蓄力阶段实际击杀 45 个敌人，p95 19.465 ms、最大 181.945 ms，连续攻击最大 51.735 ms，仍未通过。这不能直接与 35 秒、不同随机分布的上一轮计算退化比例。精确采样还分出了三条路径：批量写 Transform 时重复扫描待提交命令队列确认组件存在；没有该场景命令的存活/活动查询仍创建整场景元数据；字体图集增长再次读取和校验同一代次已保留的源字节。首次受伤音效的加载、校验和 WebAudio 缓冲转换另产生一次 56.075 ms 回调，不能混称为重复加载缓存失效。

合入主线时，新变换回归曾因误解 `FlushDeferredCommands` 的返回值而失败。该返回值表示批次已经处理，包含成功通知脚本层的拒绝；修订测试分别检查 Abort 增加、Commit 不变和 world/local 状态不变后通过，没有改动生产回滚语义。

示例同时改用更贴近原作的碎片表示：原 Godot 使用两张带 `region_rect` 的 Sprite2D；Tc 已有完整的图集子资源打包与渲染能力，因此直接将原始 256×256 纹理切为左右两个 128×256 区域。左片 pivot 为 `(1, 0.5)`、右片为 `(0, 0.5)`，PPU 为 256，配合原形状完整尺寸保持同一个旋转原点。每次死亡仍有两个半片，轨迹、寿命、旋转、渐隐、粒子数量及随机调用顺序保留；每半片从 18 个拼接条带改为一张原纹理裁切精灵。这个改动减少内部实体数，并恢复原图边缘，不能描述成继续保留 36 个条带实体。引擎对大量独立对象的通用复杂度修复另由原生批量创建/销毁回归验证。

## 验收口径

- 空挥使用与最初基线一致的八次输入，并核对每次真实输入、原生音效调用及 WebAudio 播放。
- 压力场景同时记录 rAF CPU 耗时、实际 `PlayerFrame` 耗时及回调开始间隔；帧间隔不等于显示器真正呈现的 FPS。
- 显式设置此机器的 p95 16.67 ms、最大回调 50 ms 作为迭代门槛，超限记录失败；这些是测试门槛，不能承诺所有设备零掉帧。
- 35 秒聚敌仅用于快速定位，正式对照保留 120 秒。实际击杀、清场时间与清场后负载会单独记录。
- 保留两半碎片、粒子、刀光和扫描线效果；图集半片需核对原图区域、旋转原点和打包引用，同时验证技能、死亡、暂停、全屏、音频关闭及旧版本项目兼容。
- WASM 缓冲区容量和浏览器堆快照只作趋势记录，不能单凭容量不增长断言没有内存泄漏。

## 正式版本复测发现的日志开销

整合最新前端主线后，`c2848721` 的第一次正式 120 秒复测仍记录为失败：17,993 次活动回调的 p95 为 9.095 ms，但集中击杀有一次 54.145 ms 回调超过 50 ms 门槛。实际蓄力 40 杀、连续攻击 20 杀并清场；其他阶段通过。证据位于 `.engine/rougelike-stress/2026-10-16T18-43-48-817Z-32492/`，没有用已通过的候选结果覆盖这次失败。

将 68,393 个忙闲采样与帧记录对齐后，尖峰内 41 个采样覆盖约 54.077 ms，没有大采样空洞。互斥调用栈估计为：托管解释/PInvoke 14.621 ms、投影 8.398 ms、延迟提交 8.777 ms、日志桥输出 5.135 ms、首次死亡音效建声部 4.339 ms、即时编译 2.315 ms、GC 1.286 ms，其他原生/音频工作占剩余部分。该区间没有采到字体校验或 GL 同步热点；不能将它归咎于单一调度停摆，也不能把采样估计当成精确计时。

基于该证据，示例将同一帧的击杀日志合并为一次输出，仍记录实际累计和本批击杀数。伤害、特效、随机数、声音及原生销毁时机保持；压力测试按明确批次数累计真实击杀，保留旧日志格式兼容和清场前后的归属检查。此项属于示例日志开销优化，不需要新的引擎 API 或上游补丁。
