# Shelter · 避难所

以 Tc 原生 C# 复原用户提供的 Unity Shelter demo。入口 `/games/shelter`，首页示例列表新增入口；无需登录即可游玩和下载本工程。

## 游玩

使用鼠标即可完成整个流程：点击绿色空地打开食物产出房的建造预览，点击灰蓝色空地打开城墙预览，检查费用后按图片按钮确认或取消。中央粉色格已建主城，已有建筑的格子不能重复建造。资源不足会明确显示缺少的材料和数量。

点击右下角派遣图标，在独立窗口拖动滑块选择人数，再点击确认。取消不会派出居民或扣费。探索完成后自动弹出结果窗口，确认后领取资源和返回人口。右上角设置可暂停、切换 1 / 4 / 16 倍速与声音、返回菜单；默认始终为 1 倍速。浏览器版“退出游戏”结束当前游戏并回到菜单，关闭播放器按钮可释放引擎会话。

快捷键仅作辅助：Esc 取消当前操作或打开设置，Enter 确认当前窗口，B 确认已打开的建造窗口，E 打开派遣窗口，↑ / ↓ 调整窗口中的人数，P 打开/关闭设置，M 静音。在设置窗口内 Space 切换速度。不会要求通过键盘才能完成核心操作。

每人每天消耗 200 食物，派遣也需要每人 200 食物。探索时间为 `人数 * 8 + 50` 秒。每 300 秒为一天，风暴发生在第 5、10、15、20、25、29 天。农场产出随天数增长，城墙持续累积防御。建议优先保障四座农场，再建设四座城墙；不要无休止派遣而耗尽储备。

## 原始对照与修正

保留初始资源 400 / 10 / 10 / 1、网格圈层、探索资源公式、人口净增 1、建筑成本递推、每日消耗、风暴需求及阶段建筑损失。第 29 天沿用原版直接通关行为，前五轮才检查资源阈值。风暴成功不会扣除阈值资源，保持原实现。

差异有明确边界：

- 使用 Tc SpriteRenderer、TextRenderer、AudioSource 和 MonoBehaviour 重建画面与交互；未嵌入 Unity 或 JS 游戏。
- 按 Start.unity / SampleScene.unity 的真实引用恢复原版菜单、居中的 5×5 彩色方格、建筑比例、顶部资源、底部倒计时与派遣入口，以及建造浮层、派遣滑块、完成和设置窗口。地图只用 main.png / Resource.png / build.png，不再将未被场景引用的树和石头素材当地块。
- 保留原图、字体、音乐及手绘外框。以 1920×1080 参考画布等比适配网页和全屏，修正原固定像素 UI 在右下边缘的裁切；建造浮层限制在可点击范围。修正当前渲染路径额外 sRGB 解码导致的图片变暗，保留原 PNG 颜色。
- 原版生产周期为 61 秒等待、0.2 秒延迟及约 1 秒漂字；本版统一到 63 秒，省去每栋建筑的协程和漂字对象。
- 费用在建造前统一检查并扣除，修正原版显示价格与实际扣费不同；销毁立即释放占用格。
- 每次风暴按格子顺序移除不同建筑，替代可能重复抽中同一栋、空列表异常的随机销毁。人口返还基于当前人口，不覆盖期间其他状态。
- 两条重复的预建雨带（96 个雨滴对象，可视区域约 48 个）代替 Unity 粒子系统，使用 9 秒天气过渡，雨幕期间暂时冻结模拟；原场景的粒子过渡为 1 秒准备、5 秒持续、2 秒淡出，共 8 秒。音乐完整保留，转成 22.05 kHz 单声道 Vorbis，减少解码驻留内存。音频内容来源见 `Reference/assets.json` 与保留的原文件。
- 无永久存档；关闭播放器后重新开始。面向桌面键盘和鼠标。

## 修改与重建

可用 Tc 编辑器打开 `Project.tcproj`，启动场景为 `Assets/Scene/shelter.tomcat`。运行时网格和界面由 `Assets/Scripts/ShelterGame.cs` 创建，数值及状态机在 `ShelterModel.cs`；静态场景保存摄像机、脚本挂载及素材引用。

在网站仓库执行 `npm run engine:shelter`。构建器验证 `engine.lock.json` 与 native cooker / managed API 提交一致，使用真正 Tc 编译器生成 TCPAK v8，检查每条资源 SHA-256 和托管程序集，生成源码 ZIP。工具路径可通过 `TOMCAT_PLAYER_DIR`、`TOMCAT_MANAGED_DIR`、`TOMCAT_COOK_WORKER` 指定。

重新导入原素材：`python scripts/import-shelter.py --source E:/Github/Shelter --ffmpeg <ffmpeg路径>`。原项目只读；导入清单记录来源及转换后哈希。素材文件已随示例提供，普通重建不需要 Unity、原工程或 FFmpeg。

## 验证

- `dotnet run --project tests/shelter-model -c Release`：原始数值、边界、六轮风暴和从原始资源出发的完整生存策略。
- `node --test tests/shelter.test.mjs`：包完整性、资源来源及下载工程内容。
- `node tests/shelter-interaction-browser.mjs`：真实 WASM，鼠标建造/取消、占用/资源不足、派遣滑块/取消/确认/领取、暂停、全屏与重开。默认本地端口 5199；可设 `TEST_BASE_URL`。不使用游戏状态注入。
- `node tests/shelter-performance-browser.mjs`：独立浏览器采样初始、暂停、16 倍速、全屏、自然进入第一场风暴及雨幕；记录实际引擎/包哈希、帧耗时、帧间隔、WASM 内存与音频释放。可设 `TEST_SHELTER_CPU_P95_MS` 验收本机预算，测量时避免并行构建或其他 GPU 测试。
- 原 Unity 运行参考截图在网站工作区 `.engine/shelter-unity-reference/CaptureBuild/screenshots/`，原工程只读复制后使用对应 2021.3 编辑器运行；离屏截图临时将 Overlay Canvas 对齐至原相机，截图后恢复。捕获说明见同目录上级的 reference-notes.md。

原工程许可证随 `LICENSE` 保留；参考源代码在 `Reference/`，素材来源归属保持原项目记录。
